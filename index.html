CiteLock

Deterministic, third-party re-runnable quote & citation verification. No LLM judge — just string matching and SHA-256.

Start here

Kar-Citelock tells you whether every quote attributed to a source document really appears in that source, word for word. It runs entirely in this page: nothing you paste is sent anywhere, and no AI judges anything.

  1. Add each source document (or press Load demo).
  2. Add each claimed quote and the source it is attributed to.
  3. Press Run verification.
  4. Read each quote's verdict: VERIFIED (found word for word), NEAR_MATCH (close but altered) or NOT_FOUND; keep the receipt hash.

Below the tool: how it works · words on this page · blueprint · roll it out · for a business · FAQ

Paste one or more source documents, then list the quotes an AI (or a person) claims come from them. CiteLock checks each claimed quote against its source using plain substring search and Levenshtein similarity — the same algorithm every time, inline in this page's own source code — and classifies it as VERIFIED (exact, after whitespace/quote-mark normalization), NEAR MATCH (a close but altered passage — an edited or paraphrased quote), or NOT FOUND (no matching passage exists in that source at all). The run ends with a SHA-256 receipt hash: give the same sources and the same claims to anyone, anywhere, and this exact algorithm produces the exact same hash — that is what "provable" means here, nothing more mystical than that.

Limits. CiteLock only checks whether the quoted words are in the source you supplied. It cannot tell you whether that source is genuine or unaltered, or whether it says something different elsewhere. It does not understand meaning, so a word-for-word quote can still mislead out of context. Capital letters count: a quote that differs only by a capital is a NEAR MATCH, not VERIFIED. Before comparing, only spacing, curly quotes and dashes, and Unicode's different ways of encoding the same letter are evened out. A passage 90% or more similar but not exact is a NEAR MATCH. Similarity is 1 minus the characters you would have to change, divided by the length of the longer text: changing "move" to "shift" in a 69-character sentence scores 92.75%. A quote must match whole words: "he said yes" is not VERIFIED by a source that says "she said yes" (version 1 did verify it); it is measured against the words it sits in and comes out a NEAR MATCH. In Chinese, Japanese, Thai and other scripts written without spaces, any matching run counts. A quote under three words is too short for the near-match search, so it is either found exactly (VERIFIED) or NOT FOUND. Nothing you type is sent anywhere or saved anywhere — this page runs entirely in your browser, offline, and reloading it clears everything.

How it works

  
  
  1. Source and quote are normalised the same way: curly quotes, dashes and whitespace are made uniform, so typography cannot hide a match or fake one.
  2. An exact match of whole words is VERIFIED: it must not start or end inside a word, so "he said yes" is not verified by "she said yes".
  3. Otherwise it finds the closest passage in the source that shares a run of at least three words, and scores how alike they are: 0.90 or more is NEAR_MATCH, less is NOT_FOUND.
  4. The inputs and results are hashed with SHA-256 into a receipt anyone can recompute.





  
Words on this page

  
Similarity
1 minus the number of characters you would have to change, divided by the length of the longer text. Changing "move" to "shift" in a 69-character sentence takes 5 changes: 1 − 5/69 = 92.75%, so NEAR MATCH, not VERIFIED.
Session ledger
Every check you run in this session, each entry chained to the one before by its hash, so editing any entry afterwards breaks the chain and shows.
Kernel
The small piece of code that decides every verdict; the rest of the page only shows what it decided. Here it is the block inside this page, copied byte for byte into kernel.mjs (the file the tests run) and into the script, so all three are the same code.
SHA-256 receipt
A 64-character fingerprint of the input and the verdict. Anyone with the same input gets the same fingerprint; change one character and it changes completely.
Deterministic
No AI model, no random numbers and no clock go into a verdict, so the same input gives the same verdict on any machine, every time.
No AI judge
No language model decides anything. The verdict comes from fixed rules you can read in kernel.mjs.
Mutation gate
A test of the tests. witness makes small deliberate changes to the kernel, one at a time: for example it turns if (count > 0) into if (count >= 0), then runs the tests. Every change must make a test fail. A change no test notices has survived: it would mean no test checks what happens at that exact point. A change reviewed as equivalent cannot alter any result (both versions give the same answer for every input), and the reason is written down and checked.
CI
Continuous integration: GitHub re-runs every test and the gate on its own computers on every change, and the runs are public.
In the browser
The page does the work on your computer. Nothing you paste is sent to a server.
MIT licence
An open-source licence: you may use, copy, change and build products with it, free, as long as the copyright notice stays.
Sourced figures
Every number in the cost case comes from a published source (the UK median wage and UK inflation, from the ONS), linked under the table.

Against what you do now

  
  • Searching the source by hand. Slow, and a changed word in a long quote is easy to miss.
  • Trusting the summary or the model. AI summaries can alter or invent quotes, and nothing shows which.
  • Asking a model to check. Its answer is not reproducible and cannot be recomputed by anyone else.

Where it stops, answered straight

  
  • The source itself. It confirms text is in the source you supplied, not that the source is authentic.
  • Meaning out of context. A verbatim quote can still mislead; that is a human judgement.
  • Short quotes. The near-match threshold is fixed at 0.90, so one changed word in a quote of a few words can read NOT_FOUND rather than NEAR_MATCH.

FAQ

  
Why NEAR_MATCH and not just found or not?
Because the dangerous case is a quote that is almost right: one word changed, a number altered. NEAR_MATCH says it is close and shows you it is not the same.
Can an agent run it?
Yes. The same kernel ships as a one-file Node.js script (scripts/kar-citelock.mjs), usable as an agent skill before it quotes anything.
What happens with bad, empty or very large input?
A quote naming a source that is not loaded gets SOURCE_MISSING. On the page an empty quote gets EMPTY; the script refuses one as bad input (exit 2), as it does a file without a sources list and a claims list. Quotes under three words cannot be fuzzy-matched (see Limits). There is no size cap; the near-match search takes longer on long quotes and long sources.
What do I need to run it?
For the page, a modern browser; there is nothing to install. For the script, Node.js 20 or later (free from nodejs.org; node --version shows which one you have): download scripts/kar-citelock.mjs (one file, no dependencies, no npm install) and run it with no arguments to see how to call it.
Does it need the internet or an account?
No. The page works once loaded, and the script runs offline. Nothing is uploaded.
